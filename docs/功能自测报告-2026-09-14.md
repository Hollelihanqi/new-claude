### 本轮测试隔离事故（如实记录）

终端探针第一次只改了 PowerShell `$HOME`，没有改 `%USERPROFILE%`，且后台 `--sync` 没带 `CC_MANAGER_TEST_HOME`。因此在真实 `C:\Users\hq\.claude-split` 下创建了一个只含空 `.claude` 的 `qa-delete` 目录，并触发两次真实同步。发现后已完成：

- 确认 `qa-delete` 只含空目录、不是 reparse point，随后精确删除；当前路径不存在；
- 真实 `config.json` 仍只有 hq、ba、ds、jdw，没有测试环境或测试 Key；
- 两次同步更新了 `~/.cc-manager/shared/resources.json`、`distribution.json` 和 `sync.log` 等派生状态，没有把测试数据写进去；
- 修正探针后用 `%USERPROFILE%` + `CC_MANAGER_TEST_HOME` 双重隔离重跑，终端结果全部通过。

会话较早还曾误启动不接受测试 HOME 的 release 构建，提前执行了新版的真实插件独立目录迁移。它没有混入测试数据，但让真实 hq、ba、ds、jdw 提前进入新版插件存储结构；当前 `cc.ps1` 也指向工作区 debug 程序：

```powershell
$ccm = 'E:\Dr\new-claude\src-tauri\target\debug\pathmux.exe'
```

这两项不适合在测试结束时手工逆向回滚：插件迁移包含官方 CLI 账本与独立目录，错误回滚可能损坏真实插件状态；而把新脚本指回 v2.3.8 会混用新脚本与旧同步语义。正式处理应由安装同一份新版构建重新生成脚本并接管现有迁移状态。
