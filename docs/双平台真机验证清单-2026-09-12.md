## 零、怎么记证据

## 一、A#3 严格 TLS 探测（macOS 侧完全未验证）

**背景**：本机（Windows/Schannel）已实测 `--cacert` 是**替换**信任库、且必须加 `ssl-revoke-best-effort`（自签 CA 无 CRL 分发点会 rc=60）。
而 macOS 自带 curl 是 8.7.1 + **LibreSSL（OpenSSL 分支）**，语义**可能与 Schannel 不同**。代码已按"运行时解析 `curl --version` 判断后端"来适配，但**没有在 LibreSSL 上跑过**。

| # | 步骤 | 预期 | 结果 | 证据 |
|---|---|---|---|---|
| 1.1 | 终端跑 `curl --version` | 显示 `libcurl/8.7.1 … LibreSSL`（无 Schannel） | | 复制首行 |
| 1.2 | 导入一个**公司自签网关**的 CA，保存并接入终端，重开终端，在「诊断中心」重新检测 | 网关项显示「可达，Key 有效」，且文案提到**由已导入的 CA 签发** | | 截图 |
| 1.3 | 删掉 `~/.cc-manager/ca-cert.pem` 后重新检测 | 网关项 **fail**，文案为「TLS 证书校验失败…请导入 CA 根证书」 | | 截图 |
| 1.4 | 用公有 CA 的网关（或任何公网站点）验证 `--cacert` 回退不会被打挂 | 系统信任即可通过，**不触发** `--cacert` | | 截图 |

> **重点**：1.3 是本次改动的核心语义 —— 「证书没过就绝不报可达」。若 1.2/1.3 在 macOS 上表现与 Windows 不同，说明 LibreSSL 的 `--cacert` 语义与推导不符，**需要回来改**。

> 且**必须与项目三处版本号一致** —— 想演练就得先把三处版本临时改成一个新号，或直接推正式版本号的 tag。
