## 一、核心术语

| 用词 | 含义 | 不要再说 |
|---|---|---|
| **环境** | 应用管理的**独立运行配置**：一份配置目录 + 一套网关或登录 + 一组模型档位。 | ~~实例~~、~~空间~~ |
| **网关环境** | 「环境」的一种：使用**网关地址、Key、模型映射**；应用替你配置凭据（`ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`）。 | ~~路由环境~~、~~自定义路由~~、~~公司网关路由~~ |
| **独立登录环境** | 「环境」的一种：**登录由 Claude Code 官方流程管理**，应用只隔离配置目录，不碰凭据、也不配网关与模型映射。 | ~~账户环境~~、~~独立 Claude 账户~~、~~另一个账户~~ |
| **默认 Claude** | **不是「环境」的一种。** 直接运行 `claude` 的那个账户（`~/.claude`），是**统计来源**。应用对它是**只读**的。 | ~~主账户~~、~~默认环境~~、~~默认 Claude 环境~~、~~默认实例~~ |
| **环境名** | 用户起的那段命令词（如 `corp`），也是 `claude <环境名>` 里的那段。 | ~~实例名~~、~~空间名~~ |
| **共享配置作用范围** | 三种：**所有环境**（应用统一维护并单向分发）/ **指定环境**（只写入所选环境）/ **当前项目**（用项目自身配置，不进共享库） | ~~所有空间~~、~~指定空间~~ |

### 描述启动行为时：用「使用该环境启动」

**不要**说「切换环境」「切到环境」—— 那暗示存在一个全局"当前环境"。本产品**没有**全局当前环境，每次命令独立选择。

> ✅ 「`claude corp` 使用 corp 环境启动，其他终端和默认 Claude 不受影响。」
> ❌ 「`claude corp` 切换到 corp 环境，跑完自动恢复。」

### 为什么「默认 Claude」列在这里却不是环境

它是**「本条命令用哪个环境」之外的基准**：

- 用量统计要把它算进来，数字才完整；
- 「这次用的是哪个环境」需要有一个明确的对照，才不产生歧义。

应用**从不写入它的配置**：`MAIN_PROFILE_KEY`（`__main__`）的全部用途就是扫用量（`main.rs` 的 `scan_usage_dir`）与只读地检查 `~/.claude/settings.json`（模型钉死提醒）。它也**不在环境列表里**（`profile_names` 排除 `__main__`）。

## 二、这个软件的定位（术语服务于它）

**核心价值：在同一个项目目录里，用不同终端同时跑不同网关，互不干扰；且不需要本应用在运行。**

机制上靠的是**按"每次调用"注入环境变量**，不是全局改写配置：

```bash
CLAUDE_CONFIG_DIR="$_cch" ANTHROPIC_BASE_URL=... command claude "$@"
```

`VAR=值 command` 是**命令前缀**，只对这一次调用生效，退出即消失。

### 可以自证的差异（不写对第三方产品的断言）

> **不要**把区别宣传成「另一个软件必须一直开着」——那取决于对方实现，**本仓库无法自证**。
> 以下各条都由本仓库代码可自证（依据见 [`产品模型与不可破坏约束-2026-09-12.md`](./产品模型与不可破坏约束-2026-09-12.md) §三）：

- 没有全局「当前环境」这种运行状态
- 不改写全局网关配置来完成切换
- 网关参数**只作用于当前一次 Claude 进程**
- 同一项目可以**并发**连接多个网关
- 一个终端退出或更换环境，**不影响**其他终端
- 桌面管理中心是**配置工具**，不是运行中的代理服务

### 由此得出的三条硬边界（改动时不得越过）

1. **环境的使用不得退化成"改写全局配置"** —— 一旦改成写 `~/.claude/settings.json`，就失去了本产品的定位（见设计约束文档 §一）。生成的 shell 函数必须是**命令前缀**注入，不能是 `export` 或改写全局文件。
2. **本应用不得成为运行时前提** —— `_ccm_sync` 必须永远成功（生成脚本里硬编码 `return 0`），应用没开甚至卸载也要能正常跑 `claude`。
3. **并发是常态，不是边缘情况** —— 任何"同一时刻只允许一个"的假设都要先检查是否会影响多个终端并跑。

> 相关：CA 信任库是**全局共享且累积**的（`import_cert` 追加去重，`NODE_EXTRA_CA_CERTS` 指向同一个 bundle），
> 所以**多个自签网关的 CA 可以共存、同时受信任** —— 这是"同目录多网关并存"的必要前提。

## 三、不受本表约束的词

以下**不是**本表的对象，保持原样 —— 它们指的是别的东西：

| 词 | 为什么不动 |
|---|---|
| `instanceId`、`instance_dir`、`InstanceSettings`、`profile_runtime_info` 等标识符 | 协议字段与代码标识，改名会破坏接口与存量配置 |
| `~/.claude-split/`、`~/.cc-manager/` | **真实目录名**，改了会断掉存量用户的配置 |
| 网关 / 代理 / 证书 / 信任库 | 有确定技术含义的标准词 |
| 终端集成 / Shell / 环境变量 | 同上 |
| WorkBuddy / MCP / Codex / cc-switch | 第三方产品名（`cc-switch` 在用量统计里是对**第三方项目**口径的署名引用） |
| 「环境变量」「运行环境」「单实例」等固有用语 | **同字不同义**，不要误改（尤其「单实例」= single-instance 应用） |

## 四、写作约定

1. 首次出现可用「环境（原「实例」）」过渡一次，之后一律用「环境」。
2. 两个子类需要区分时写全「独立登录环境」「网关环境」，不要简写成「账户」「路由」。
3. 命令与路径保持原样：`claude <环境名>`、`~/.claude-split/<环境名>/.claude`。
