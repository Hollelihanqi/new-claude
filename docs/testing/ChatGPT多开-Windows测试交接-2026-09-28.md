# ChatGPT 多开：Windows 测试交接

## 功能背景

PathMux 新增「ChatGPT 多开」：复用本机安装的官方客户端，为不同账号创建独立的桌面数据、Codex 数据、SQLite 数据和文件凭证目录。同时提供**本地 Codex 工作记录**的选择性复制，让目标账号在独立副本上继续工作。

本次范围包括实例创建、启动、聚焦、退出、残留崩溃报告进程清理、隔离与账号检查、删除，以及本地记录预览、批量复制、创建实例时选择导入来源、项目目录重定向、去重、暂停、重启恢复与撤回未完成副本。切换账号时可选择单条会话、整个项目或全部本地会话；目标实例会打开导入的独立副本。

记录适配支持旧版 JSONL、新版分页记录、分支父链、`.jsonl.zst` 压缩记录和可读取的 PNG/JPEG/GIF/WebP 本地图片。父链按原始字节和序号边界取快照；目标生成独立记录，不共用来源的数据库、登录凭证或可写历史。

### 明确边界

- 普通 ChatGPT 聊天和云端任务按账号保存在云端，不会出现在本地 Codex 记录列表中，也不支持跨账号复制。官方文档说明 Quick chat 与 Codex 聊天分属不同列表：[Projects and chats](https://learn.chatgpt.com/docs/projects)。账号权限控制的远程文件及工具授权也不复制；遇到不能独立迁移的引用会拒绝复制。
- 项目文件不随会话复制。可以选择新的项目目录；两边选择同一目录时，仍操作同一份项目文件。
- 单个持久化队列最多 100 条；选择“全部本地会话”时自动拆分为多个队列。扫描安全上限为 10,000 个文件；达到上限或遇到损坏记录时，项目/全部同步会阻止执行，避免误称完整。单条合并历史及附件最多 32 MB，单张本地图片最多 8 MB，父链最多 128 层。
- 切换时同步已完成的本地会话；不同账号不共用认证、数据库或可写会话。用户要求所选项目在两个窗口同时打开时后台实时同步；当前版本尚未实现，不能把按次复制验收成实时同步。Mac 隔离实验已确认官方 `thread/inject_items` 不会生成目标窗口的可见问答，原因与接口边界见[技术调研第 11 节](../ChatGPT桌面多开技术调研与接入方案-2026-09-28.md)。用户随后要求先发布正式版本，本缺口在发布说明中明确披露，仍需单独开发和验收。
- 目录隔离不等于操作系统安全沙箱，同一系统用户仍可访问本机文件。

用户安排：开发者完成 Mac 本地测试；Windows 真机测试由用户切换环境后执行。本文件记录待执行步骤，不表示 Windows 真机已经通过。安全确认提交 `fc1e9f3` 的 [Windows/macOS 自动检查](https://github.com/Hollelihanqi/new-claude/actions/runs/36400774651) 均已通过。

Mac 基线：官方 ChatGPT `26.924.22138` 上已运行两个独立实例，官方本地会话服务确认各自数据目录和两个不同账号标识；两者分别关闭、重启后标识仍在。合成工作记录的旧版、新版分页/压缩分支、批量复制与中断恢复均通过官方客户端测试。早期真实本地会话的临时目标曾向本机模拟模型服务发送包含旧上下文和新提问的续聊请求；当前增长后的大型真实会话可见历史和模型历史核验通过，但本地续聊测试只观察到历史请求，未观察到新提问；这没有调用真实账号的云端模型。首次桌面演示暴露出“标题只有 ID、目标窗口正文空白”的缺陷；新版已改为从消息生成标题，迁移并核验官方可见消息。重建后的 PathMux 界面再次实测单条会话从默认实例同步至 B：显示 1 条成功，B 独立目录有 25 条用户消息和 74 条助手消息的快照，官方本地会话服务已核验目标可见问答，进程携带目标会话链接启动。用户目视确认 B 窗口显示正文与过往问答。Windows 的包身份、登录回调、窗口行为与数据落点仍需按下表实测。

## 测试准备

1. 拉取 `main`，确认包含 `src-tauri/src/chatgpt/snapshot.rs`、`batch.rs` 和 `src/components/ChatGptPanelHistory.tsx`。
2. 安装项目所需 Node、pnpm、Rust、Visual Studio C++ 构建工具及 WebView2。
3. 安装基于 Codex/Electron 的官方 ChatGPT 客户端，并正常打开一次。旧版原生客户端若没有独立目录能力，应被明确拒绝。
4. 准备两个可使用的测试账号 A/B，以及不包含敏感内容的测试项目目录，例如 `C:\PathMux Test\中文项目`。
5. 先关闭其他开发版 PathMux。正式实例可以保留，但两套 PathMux 不应同时管理同一批测试数据。
6. 记录 Windows 版本、CPU 架构、ChatGPT 版本、安装渠道（Store/MSIX 或普通安装）、应用路径及测试提交号。

测试数据位置：`%LOCALAPPDATA%\PathMux\chatgpt\profiles\<UUID>`。名称只是标签，不能代替官方窗口显示的实际账号。

## 自动化检查

在仓库目录的 PowerShell 执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm test -- --run
cargo test --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
git diff --check
```

安装了官方客户端后，可以运行真实客户端的合成记录测试。这些测试使用临时目录和本地模拟响应服务，不使用真实账号，不调用云端模型：

```powershell
# 自动发现不成功时，填写界面选择过的官方主程序路径。
$env:PATHMUX_TEST_CHATGPT_APP = 'C:\实际安装位置\ChatGPT.exe'
cargo test --manifest-path src-tauri/Cargo.toml official_client_migrates_legacy_context_without_credentials -- --ignored --nocapture
cargo test --manifest-path src-tauri/Cargo.toml official_client_pagination_batch_and_crash_recovery -- --ignored --nocapture
Remove-Item Env:PATHMUX_TEST_CHATGPT_APP -ErrorAction SilentlyContinue
```

第二项覆盖压缩父记录、分页子分支、父记录后来新增内容的排除、批量检查点丢失、RPC 返回丢失、来源删除后恢复，并核验官方客户端实际发向本地测试服务的续聊上下文。

Mac 专用的窗口生命周期测试在 Windows 上不会运行，需按以下步骤人工验证。
