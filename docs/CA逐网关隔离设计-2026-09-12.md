# CA 逐网关隔离 —— 设计与迁移方案

> **日期**：2026-09-12
> **来源**：审查 2026-09-12 第 3 条（High）。**已核实成立**：
> `cert_path()` 只有一个 `~/.cc-manager/ca-cert.pem`，`import_cert` 追加去重进这一个文件，
> 而**每个 router 都注入它** ⇒ 给网关 A 导入的私有 CA 同时成为网关 B 的信任根
> （`NODE_EXTRA_CA_CERTS` 对 Node 是**追加**语义，B 用的是"系统根 ∪ 这个全集"）。
> 这与约束 5「网关环境的 Key、地址、CA、模型映射彼此隔离」直接冲突。
> **状态**：**已实现**（2026-09-12）。§七 的七条验收标准见下方实现记录；
> **未验证**：macOS 侧的 `security` / Keychain / `NODE_EXTRA_CA_CERTS` 行为本机无法验证。

## 实现记录（2026-09-12）

| 步骤 | 落地 |
|---|---|
| 路径与名字校验 | `ca_dir()` = `~/.cc-manager/ca/`；`ca_bundle_file()` 挡路径字符（**不**回退哈希名） |
| 导入 | `import_cert_into(envs, path)`：**按网关注入**、块级去重、写**原文 PEM 块** |
| 清空 | `clear_certs_from(envs)`：删文件 → 算其余网关并集 → `certs_to_revoke` 只撤销**不再被任何网关使用**的证书 |
| 生成脚本 | 两个 Shell 都注入 `ca/<环境>.pem`；断言里钉住"不得再出现 `ca-cert.pem`" |
| curl 探测 | `detect_models_ladder(env, …)` 用**该网关**的 bundle 作 `--cacert` 回退 |
| 迁移 | `migrate_shared_ca_once()`：复制给每个网关 + 标记文件；排在脚本自愈**之前**（否则存量用户会断） |
| WorkBuddy | 按 §四 **A**：`union_ca_bundle_path()` 派生一个并集文件供它使用；导入仍作用于所有网关（`import_cert` 兼容入口） |
| 界面 | 目标网关 `Select`（默认「所有网关环境」）+ 范围化文案与后果说明 |
| 测试 | `ca_bundle_names_reject_path_characters` / `pem_comparison_ignores_whitespace_but_keeps_writable_blocks` / `a_cert_still_used_by_another_gateway_is_never_revoked`；bash 行为测试断言注入的是 `ca/corp.pem` 且不含 `ca-cert.pem`；前端 `CaCertButton.test.tsx` 3 条 |

**过程中被测试抓到的一个自身缺陷**：`pem_blocks` 最初把空白**全部**去掉再返回，
连 `-----BEGIN CERTIFICATE-----` 里的空格也没了 —— 写回文件就是非法 PEM，curl/Node 都读不了。
修法：**原文块用于写入，`norm_pem` 只用于判等**，并用测试钉住。

**仍未验证**：macOS 全链路；真实网关的自签证书端到端（本机没有可用的自签网关）；
Windows 用户 Root 库的撤销范围（不拿用户证书库做实验）。

## 二、机制：每网关一个 bundle

```text
~/.cc-manager/ca/<环境名>.pem      ← 每个网关环境各一份，互不合并
```

- 生成脚本注入 `NODE_EXTRA_CA_CERTS=<该网关的 bundle>`；文件不存在就**不设置**（沿用现值语义）。
- bundle 名由环境名派生，但**必须挡住路径字符**（`/` `\` `:`、`.`/`..`、控制字符）；
  名字不安全 → 拒绝导入并说明原因（不静默改用哈希名，那会让人找不到文件）。
- **不做"共享 bundle + 网关 bundle 的并集"**：任何全局共享的 CA 按定义就是所有网关都信任，
  等于把这条缺陷换个名字留下。便利性靠 §五 的"应用到所有网关环境"**循环**解决，不是靠共享文件。

## 三、清空/撤销：范围必须重算

`clear_certs` 现在会：撤销本应用加进 WorkBuddy `ca.pem` 与 Windows 用户 Root 的证书，再删本地 bundle。
按网关拆分后不能照搬 —— **从网关 A 删掉的证书，可能仍被网关 B 需要**。

规则：

1. 删除网关 `X` 的 bundle；
2. 计算其余所有 bundle 的**并集**；
3. 只撤销"**删掉的那份里有、且并集里已经没有**"的证书；
4. 一条都不撤销时也要如实说明（"该证书仍被 N 个网关使用，未撤销外部信任"）。

`managed-certs.json`（所有权记录）保持**全局**：它回答的是"这张证书是不是本应用装的"，
与"装给哪个网关"是两件事。加一个**记录归属**的字段即可（迁移时按"所有网关"回填）。

## 四、WorkBuddy 的作用范围（**需要你定**）

现状：`import_workbuddy_ca` 先调 `import_cert`，于是那张 CA
「同时进入应用信任库、**被所有托管 Claude 实例信任**」（这条文案已写进界面确认框）。

按网关注入后，这句话不再自动成立。可选：

| 选项 | 含义 | 代价 |
|---|---|---|
| **A（推荐）** | WorkBuddy 导入作用于**所有网关环境** | 保持现状语义，界面文案不用改；WorkBuddy 通常就一个公司网关 |
| B | WorkBuddy 导入也弹"目标网关"选择 | 更精确，但两个导入入口的作用范围模型不一致 |
| C | WorkBuddy 导入**不再**写入任何 Claude 网关的 bundle | 最隔离，但会让"WorkBuddy 能用、Claude 网关不能用"变成常见故障 |

## 五、界面

顶栏「CA 证书」增加**目标网关**选择：

- 默认 = 当前选中的环境（没有选中时要求先选）；
- 选项 = 所有**网关环境**（独立登录环境不需要网关 CA，不列出）；
- 复选「应用到所有网关环境」—— 它是一次**循环导入**，不是共享文件，所以之后仍可逐个清理；
- 顶栏徽章的张数必须带范围（如「网关 corp：2 张」），不能只给一个全局数字 ——
  那正是当前误导的来源。

## 六、迁移（**不可破坏存量**）

存量用户只有一份 `ca-cert.pem`，且**所有** router 都在用它。

1. 首次运行：若 `ca-cert.pem` 存在且 `~/.cc-manager/ca/` 尚不存在 → 把它**复制**给
   **每一个网关环境**，写一个版本标记，避免重复执行。
2. **旧文件不删、不改**（用户可能还在别处引用它），只是不再被注入。
3. 迁移后给出提示：**"已把原有 CA 分配给全部 N 个网关环境；不再需要它的网关可以逐个移除。"**
   —— 不这么说的话，隔离等于没有发生，而用户不知道。
4. 迁移**只影响 router**：独立登录环境本来就不注入 CA。

---

## 七、验收标准

1. 给网关 A 导入的 CA，**不出现在网关 B 的 `NODE_EXTRA_CA_CERTS`**（两个 Shell 都要测）。
2. 网关 A 的 CA 文件独立存在；导入/清空只动 A 的文件。
3. 从 A 清掉、但 B 仍在用的证书，**不得**被撤销出 Windows 用户 Root 库 / WorkBuddy bundle。
4. 存量用户升级后，原有自签网关**仍能连上**（迁移后脚本注入的是复制出来的那份）。
5. 顶栏张数带范围，不再呈现"全局共享"的暗示。
6. 名字含路径字符的环境：拒绝导入并说明原因。

---

## 八、实现顺序（每步都要两个平台一起）

1. 路径与名字校验（纯函数，可测）
2. `import_cert` / `clear_certs` 改按网关 + 撤销范围重算（纯函数 `certs_to_revoke`，可测）
3. 两个生成脚本 + curl 探测回退改用该网关的 bundle（**必须与迁移同批**，否则存量用户会断）
4. 迁移（复制 + 标记 + 提示）
5. WorkBuddy 作用范围（按 §四 的裁定）
6. 界面：目标网关选择 + 范围化徽章
7. 回归测试：跨网关隔离、撤销范围、迁移后仍可用
