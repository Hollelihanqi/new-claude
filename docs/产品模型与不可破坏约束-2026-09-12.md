## 一、产品定位（一句话）

> **本产品的核心不是"切换 Claude 配置"，而是让同一个项目中的多个终端，以互不干扰的方式同时连接不同网关。**

```
项目目录
├─ 终端 A：claude            → 官方 Claude，保持原样
├─ 终端 B：claude corp       → 公司网关
├─ 终端 C：claude test       → 测试网关
└─ 终端 D：claude partner    → 合作方网关
```

这些终端**同时运行**。**关闭管理中心不影响已生成的命令与后续启动。**

### 用户不应感知"当前环境"

没有全局的"当前选中环境"这种运行状态。**每次启动命令独立决定用哪个环境。**

## 二、对象模型

| 对象 | 定位 | 应用权限 |
|---|---|---|
| **默认 Claude** | 用户直接 `claude` 启动的官方环境 | **只读统计**，不修改配置 |
| **网关环境** | 网关地址 / Key / 模型映射 / 独立会话目录形成的启动预设 | 应用负责配置与删除 |
| **独立登录环境** | 独立的 Claude 配置目录；登录由 Claude Code 官方流程完成 | 只创建隔离目录，**不接管登录凭据** |
| **全局共享资源** | Skills / Plugins / Agents / Commands 等跨环境资源 | **应单独定义**，不得混同于默认 Claude |
| **默认 Claude** | **不是一种可配置环境，也不是同步中心。** 只是统计中的一个来源，表示"直接运行官方 `claude` 产生的数据" | 仅统计 |

## 三、与 cc-switch 的区别（只写我们能自证的）

> **不得**宣传成"另一个软件必须一直开着" —— 那取决于对方实现，不是可靠结论。以下各条均由本仓库代码可自证：

- 没有全局"当前环境"。
- 不改写全局网关配置来完成切换。
- 网关参数**只作用于当前一次 Claude 进程**。
- 同一项目可以**并发**连接多个网关。
- 一个终端退出或更换环境，**不影响**其他终端。
- 桌面管理中心是**配置工具**，不是运行中的代理服务。

### 界面措辞要求

**不要**用「切换到环境」「跑完自动恢复」。应说：

> 仅本次命令使用该环境，其他终端和默认 Claude 不受影响。

## 五、不可破坏的产品约束

1. `claude` 必须**无条件透传官方 CLI**：零写入、零同步、零环境变量污染。
   **透传的范围要写准（2026-09-12 收窄）**：承诺的是**参数与原生退出码**透传。
   PowerShell 的函数包装器**无法**让调用方的 `$?` 反映原生进程的失败（本机实测：
   能改变 `$?` 的只有 `$PSCmdlet.WriteError`，而它要求 advanced function，会破坏参数透传），
   所以 PowerShell 下请用 `$LASTEXITCODE` 判断结果 —— 该值由脚本**显式回写**，
   成功为 0、失败保留原始非零值。**不得承诺"PowerShell 状态语义完全一致"。**
2. `claude <环境名>` **只影响本次子进程**。
3. **不保存**"当前选中环境"这种全局运行状态。
4. 默认 Claude **只参与洞察统计**，不参与配置修复与双向同步。
5. 网关环境的 **Key、地址、CA、模型映射彼此隔离**。
6. 独立登录环境**只隔离目录**，认证完全交给 Claude Code。
7. **管理中心关闭后，已配置环境仍能启动**。
8. **同一项目、多个终端、多个网关**必须作为主要测试场景。
9. 环境名应**避开 Claude 官方子命令**（如 `mcp`、`doctor`、`update`），防止 `claude mcp ...` 被误认为环境。
10. 后续增加统一的 **`ccm <环境名>` 启动器**：解决 cmd.exe，并让 PowerShell / bash 包装函数最终都调用同一套启动逻辑。

## 六、整改优先级

先保证默认 `claude` 完全无副作用，再依次拆除默认 Claude双向同步与模型修复，随后处理 CA 注入、共享资源归属、统计扫描范围。

> **第 9 条建议提前**：它不是架构问题、是**现成的坑** —— `generate_sh` 的 `case "$1"` 直接拿第一个参数匹配环境名，
> 若有人把环境命名为 `mcp`，则 `claude mcp add ...` 会被当成切环境。`valid_name` 目前只挡字符集、
> `__` 前缀与 Windows 保留名，**未挡 Claude 子命令**。

## 七、已确认的决策（2026-09-12 用户裁定）

> 上一版此处为「待确认」的 4 点，现已全部裁定。**以下为实现依据，不得自行偏离。**

### 7.1 `ccm` 启动器 —— 留到重构后再说

本轮**不做** `ccm`。先把五件事做完：默认 `claude` 零副作用、拆双向同步、CA 注入、共享资源归属、统计口径。
`ccm` 单独立项。**B#7 的 cmd.exe 结论因此暂不变更**（仍为「未支持」）。

### 7.2 共享 MCP —— 应用自建共享源，**单向分发**

共享 MCP 归应用管理：

```text
~/.cc-manager/shared/mcp.json
                 ├─ 单向分发 → 环境 corp
                 ├─ 单向分发 → 环境 test
                 └─ 单向分发 → 环境 partner
```

**默认 Claude 的 `~/.claude.json` 完全不参与。**

界面需明确**三种作用范围**：

| 作用范围 | 语义 |
|---|---|
| **所有环境** | 由应用统一维护并**单向分发** |
| **指定环境** | 只写入所选环境 |
| **当前项目** | 使用项目自身的 MCP 配置，**不进入**全局共享库 |

- **删掉**现有这句：「MCP 与插件启用状态在每次启动 Claude 时双向同步。」
- **替换为**：「应用管理的共享配置会自动分发到所有环境；各环境自己的配置保持独立。」
- 实现上**必须坚持单向分发**，避免再次形成复杂的多副本双向合并。
- 环境里出现**同名 MCP** 时，**环境配置优先**，但**必须显示冲突提示**。

### 7.3 共享资源迁移 —— 复制 + 原子切换环境链接

**不移动、不删除、不链接默认 Claude；复制后只切换受管理环境。**

> 上一版设想的「移动内容」是错的：那会删掉 `~/.claude/` 里的东西；即便随后给默认 Claude 建链接，
> 也等于继续干预默认 Claude，违反"只读"约束。

步骤：

1. **复制**（不是移动）到应用共享目录：
   `~/.claude/{skills,plugins,agents,commands}` → `~/.cc-manager/shared/{skills,plugins,agents,commands}`
2. `~/.claude/` 原内容**保持不动**，默认 Claude 继续用自己的资源。
3. 把所有**受管理环境**的链接改指向 `~/.cc-manager/shared/`。
4. 迁移后两边正式独立：默认 Claude 用 `~/.claude/`，受管理环境共享 `~/.cc-manager/shared/`，**后续不再自动互相同步**。
5. **同名处理**：
   - 内容相同 → 直接去重
   - 同名但内容不同 → **不覆盖**，保留原文件并**报告冲突**
   - 不能自动判断的插件目录 → **停止切换链接，保持旧状态**
6. **必须可回滚**：
   - 先复制到临时目录并**校验文件数量与内容**
   - 记录每个环境**原来的链接目标**
   - 全部复制成功后才切换链接
   - 任一环境重建链接失败 → **立即恢复所有旧链接**
   - 成功后记录**迁移版本**，避免重复执行

> 迁移后虽然有两份内容，但含义不同：一份属于默认 Claude，一份属于受管理环境。
> 这不是"两套共享根"，因为默认 Claude 那份**不再参与环境共享**。

界面提示：

> 已将现有扩展复制到应用共享库。默认 Claude 的原有文件保持不变；受管理环境今后使用独立的共享资源。

### 7.4 默认 Claude模型钉死 —— 保留只读告警，删除一键修复

**「只读」不等于不能检查。** 应用可以发现风险并说明原因，但**不能替用户改写**默认 Claude 的配置。

提示文案：

> 检测到默认 Claude 配置固定使用模型 `{model}`。当你从用户主目录启动网关环境时，
> 该设置可能覆盖环境的模型映射。应用不会修改此配置。建议从实际项目目录启动；
> 如需调整，请在 Claude Code 中自行修改。

处理规则：

- 只**读取并识别** `model` 字段
- **不显示**「一键恢复」按钮
- **不自动删除或改写**字段
- **只在存在网关环境时**提示
- 明确说明主要影响「**从用户主目录启动**」的场景
- **诊断详情中可展示文件路径**，方便用户自行处理
