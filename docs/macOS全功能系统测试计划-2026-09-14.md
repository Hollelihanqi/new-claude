# 并路 PathMux macOS 全功能系统测试计划

> 日期：2026-09-14
> 目标：让 macOS 上的 AI 测试人员对当前候选版本进行一次可复查的全功能系统测试
> 适用范围：Apple Silicon 与 Intel 架构的 macOS 13 及以上；主验证机建议使用当前仍受支持的最新 macOS
> 参考基线：Windows 全功能结果见《功能自测报告-2026-09-14.md》；历史平台风险见《双平台真机验证清单-2026-09-12.md》

## 一、交给 macOS 测试 AI 的任务

请把本文件作为测试任务书执行，而不是只阅读代码或只运行单元测试。必须启动真实 Tauri 桌面程序，逐个操作页面、按钮、表单、确认框、文件选择器和终端命令。每项测试都要记录结果与证据；看到失败后先保留现场、缩小复现步骤，再判断是否修改代码。

测试完成必须交付：

1. 一份填写完整的 macOS 测试报告；
2. 每个测试编号的通过、失败、阻塞或不适用状态；
3. 失败项的截图、日志、输入、期望、实际结果和最短复现步骤；
4. 测试前后默认 Claude、PathMux、Codex、WorkBuddy 关键文件的哈希与残留扫描；
5. macOS 版本、芯片、Shell、Claude Code、Codex、WorkBuddy 和被测 Git commit；
6. 对“可以发布 / 不可以发布”的明确结论，不能用“基本正常”代替。

测试 AI 不得把以下情况写成通过：

- 只看源码推断，没有实际操作；
- Tauri command 单独调用成功，但界面按钮没有点击；
- 开发网页能打开，但 `.app` 桌面程序没有启动；
- CI 编译成功，但 Keychain、Shell、LaunchServices 或文件权限没有真机验证；
- 提示了成功，但目标文件、进程环境或终端行为没有核对；
- 某一步因为缺少 WorkBuddy、真实 Claude 会话或测试证书而跳过，却仍宣称全功能通过。

## 二、最高优先级的安全规则

### 2.1 两条测试通道必须分开

**通道 A：隔离开发测试。** 用于大量增删改、错误注入和自动化操作。只允许启动 debug 构建，并在启动进程前设置唯一的 `CC_MANAGER_TEST_HOME`。Release 构建不接受这个隔离开关，绝不能拿 Release 构建做隔离目录实验。

示例目录：

```bash
export PATHMUX_QA_HOME="$(mktemp -d /tmp/pathmux-mac-qa.XXXXXX)"
export CC_MANAGER_TEST_HOME="$PATHMUX_QA_HOME"
pnpm tauri dev
```

**通道 B：安装、升级和真实 Shell 集成。** 必须使用新建的 macOS 测试用户，或者可恢复快照的测试机。该用户内不得有个人 Claude、Codex、WorkBuddy 配置。安装包会使用真实 `HOME`、真实默认钥匙串和真实 Shell 配置，不能用开发隔离目录假装完成。

### 2.2 禁止碰真实用户数据

- 不在日常使用的 macOS 账户中测试删除、迁移、CA、Shell 配置或插件操作。
- 所有环境名加唯一前缀，例如 `qa-mac-router`、`qa-mac-login`、`qa-mac-delete`。
- 所有 Key 使用测试字符串，例如 `qa-mac-secret-20260914`，禁止使用公司或个人真实 Key。
- 自签 CA 必须为本次测试临时生成，并记录指纹。不要修改系统钥匙串的信任设置，除非测试步骤明确要求且有恢复方案。
- 删除前必须用 `realpath`、`find` 和 `ls -la` 确认目标位于测试 HOME 内。遇到符号链接时不得递归删除；先移除链接本身，再处理普通目录。
- 任何命令若将要写入真实用户的 `~/.claude`、`~/.codex`、`~/.workbuddy`、`~/.cc-manager`、`~/.claude-split`，先停止并确认当前属于通道 B 的一次性测试用户。

### 2.3 Keychain 不是由测试 HOME 隔离的

macOS 网关 Key 使用系统 Keychain。即使设置了 `CC_MANAGER_TEST_HOME`，Keychain 条目仍写入当前用户的默认钥匙串，service 形如 `cc-manager:<环境名>`。因此：

- 通道 A 只使用唯一的 `qa-mac-*` 环境名；
- 保存前记录相应条目不存在；
- 删除环境后确认相应 Keychain 条目已经删除；
- 更稳妥的自动回归测试使用临时钥匙串，并在结束时恢复原默认钥匙串；
- 不得批量删除所有 `cc-manager:*` 条目。

### 2.4 立即停止条件

出现以下任一情况，停止后续写操作，保存现场并报告：

- 默认 Claude 的文件哈希在只读测试中变化；
- 测试对象出现在真实用户目录；
- 删除目标解析到测试根目录之外；
- Key 明文出现在 `config.json`、终端集成脚本、诊断报告或配置备份；
- 应用对远程 `http://` 地址实际发出了带 Key 的请求；
- 同名环境截获了 `claude mcp`、`claude doctor` 或其他官方子命令；
- 部分迁移失败后仍写入“迁移完成”标记，或者原数据无法继续使用；
- 安装包升级破坏旧版环境、插件目录或会话历史。

## 四、测试夹具

### 4.1 假 Claude CLI

准备一个可执行的假 `claude`，记录以下内容并按测试需要返回指定退出码：

- 收到的完整参数；
- `CLAUDE_CONFIG_DIR`；
- `ANTHROPIC_BASE_URL`；
- 是否收到 `ANTHROPIC_AUTH_TOKEN`，日志只记布尔值和长度，不打印内容；
- 三个模型映射变量；
- `NODE_EXTRA_CA_CERTS`；
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`。

它还要模拟 `--version` 和插件 install、enable、disable、update、uninstall 命令，以便验证 PathMux 是否真的通过各环境的官方 CLI 执行插件操作。涉及插件真实兼容性时，再使用真实 Claude Code 做第二轮。

### 4.2 本机测试网关

在 `127.0.0.1` 启动两个只供本次测试使用的网关：

- HTTP 回环网关：验证回环地址允许、模型列表、MCP HTTP 和 WorkBuddy 请求；
- HTTPS 自签网关：使用临时根 CA 签发，用于严格 TLS、逐网关 CA 与 WorkBuddy `open --env`。

网关至少提供与当前代码相容的 models、Anthropic messages 和 OpenAI chat completions 响应，并记录请求路径、状态码及是否带鉴权头。日志不得记录 Key 原文。模型固定返回：

```text
qa-opus
qa-sonnet
qa-haiku
claude-filtered-for-workbuddy
```

Claude 模型检测应显示 4 项；WorkBuddy 模型选择应过滤 `claude-` 项，只显示 3 项。另准备远程局域网 `http://<非回环地址>:<端口>`，只验证请求在发送前被拒绝；网关日志中不得出现该请求。

### 4.3 Skill、Agent、插件与项目夹具

准备：

- `qa-skill/SKILL.md`，包含清楚的版本标记 `v1`，之后改为 `v2`；
- `qa-agent.md`，包含有效 frontmatter，并引用一个存在的 Skill；
- 一个缺少 Skill 或 MCP 依赖的 Agent；
- 一个假插件 `qa-plugin@qa-marketplace`；
- 两个项目目录，其中一个路径带空格和中文；
- 一个 stdio MCP，可执行后返回固定握手结果；
- 一个包含 env/header 密钥的 MCP JSON，用于脱敏测试。

### 4.4 默认 Claude 只读基线

在测试用户中准备最小的默认 Claude 数据：一个 Skill、一个 Agent、一个插件发现记录、一条 MCP，以及两份同模型用量记录。操作开始前，对以下内容生成“相对路径 + 内容 SHA-256”的全树哈希：

```text
~/.claude/
~/.claude.json
```

测试结束再生成同口径哈希。除专门验证“Claude Code 自己运行后会写数据”的步骤外，PathMux 操作不得改变默认 Claude。若真实 Claude 必须运行，分别记录运行前、Claude 自身运行后、PathMux 操作后的三段哈希，避免把 Claude 自己的写入误判为 PathMux 写入。

- 真实 `.zshrc`、`.bash_profile`、`.bashrc` 没有隔离脚本路径；
- Keychain 只删除本次明确创建的 `cc-manager:qa-mac-*` 条目；
- `/tmp` 中的测试根可安全删除，且没有链接指向根目录外后再递归处理。

### 16.2 一次性测试用户

保留报告与证据后，可直接删除整个 macOS 测试用户及其 home。删除前导出：

- 最终测试报告；
- 截图与日志；
- 诊断报告和脱敏备份；
- 测试前后哈希；
- Keychain 测试条目清单，只保留 service/account，不导出密码；
- 安装包哈希与签名/架构检查输出。

在报告中搜索所有测试 Key 原文。若原文出现在诊断、备份、同步日志或网关日志，按安全缺陷处理。WorkBuddy 和 MCP 的业务配置文件允许按产品披露保存明文，但文件权限与界面说明必须准确。

3. 默认 Claude 只读哈希成立；
4. 删除、迁移失败和部分批量失败均验证了回滚或保留原数据；
5. Apple Silicon 真机通过；若产品承诺 Intel，则 Intel 真机也必须通过；
6. 真实 Claude Code 会话验证 Skill 热加载与插件重载提示；
7. 安装包首次安装、覆盖升级、再次启动和卸载后官方 CLI 均正常；
8. Windows 与 macOS GitHub Actions 同时通过；
9. 没有 P0/P1 阻断缺陷，也没有未解释的数据变化或敏感信息泄漏。
