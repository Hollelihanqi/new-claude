### 热路径重复磁盘 IO（性能）

- `workbuddy.rs:1278` `build_state()` — 单次调用 models.json / organizations.json **各读 4–6 次**（`repair_managed_models` + 自身 + `read_organizations` 内部叠加），且 8 处写命令结尾都 `Ok(build_state())`，等于「写完再全量重读多遍」

- `affected_source_ids@2380` 镜像了同样的双读

**建议**：`read_doc` 返回时用已读 bytes 顺带算 revision，二者合并为一次 `fs::read`。

## 四、安全（人工直接核查，结论偏正面）

### 核查过、写得好的地方

- CA 导入 PowerShell 脚本（`workbuddy.rs:346-372`）：PEM 走 **stdin** `[Console]::In.ReadToEnd()`，不拼进脚本；`mode` / `operation` 是固定字面量 → 无注入
- `certutil.exe`（`workbuddy.rs:1905`）：固定参数 + `.arg(证书路径)`，非 shell 拼接 → 安全
- shell PATH 探测（`claude_cli.rs:424-436`）：固定 marker，无用户输入
- 网络：`validate_request_url@2420` 强制 HTTPS、http 仅允许回环（SSRF 缓解）；`redact_gateway_text@2742` 在返回前脱敏 Authorization / apiKey（后端脱敏，不只靠前端防 XSS）
- 前端无 `dangerouslySetInnerHTML` → 无 XSS 注入面

### 值得留意

- **186 处** `let _ =` / `.ok()` / `unwrap_or_default()`（workbuddy 23、main 44、storage 30）。多数是合理的 fire-and-forget 清理，但密度偏高，建议专项过一遍确认没有掩盖真实失败的静默错误
